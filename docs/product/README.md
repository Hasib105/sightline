# Product Documentation

This folder contains the product-spec package for the academic integrity platform.

The package is designed to be read in order:

1. [01-product-requirements.md](./01-product-requirements.md)
2. [02-domain-workflows-and-data.md](./02-domain-workflows-and-data.md)
3. [03-system-architecture.md](./03-system-architecture.md)
4. [04-delivery-validation-and-roadmap.md](./04-delivery-validation-and-roadmap.md)

The intent is straightforward:

- user stories describe what users want to achieve
- EARS requirements turn those outcomes into verifiable product behavior
- domain workflows and data define the operational model behind that behavior
- system architecture and delivery slices explain how the product should be built and validated

This package is the implementation anchor for a unified platform that includes:

- AI-assisted live exam monitoring from CCTV feeds
- faculty-facing at-risk student analytics
- student-facing schedules and reminders

The platform is intentionally framed as an `academic integrity and academic operations support system`, not an autonomous disciplinary engine.
